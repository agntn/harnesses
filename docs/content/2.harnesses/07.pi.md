title: Pi
description: Pi Coding Agent. Every invocation mode, native model listing with fuzzy search, JSONL sessions with UUIDv7 ids, prompt templates as slash commands.

::harness-facts{id="pi"}
::

Pi is the reference harness for this package, because it supports everything: `--no-tools` for the advisor, `--tools read,grep,find,ls` for a read-only agent, `--mode json` for structured output on all of them, `--model` for selection and `--list-models` with an optional fuzzy filter. `listModels` parses that output into the shared `AvailableModel` shape; it lists only providers with configured authentication, so an empty result is a credentials question, not a bug.

That read-only list is strict. Extension tools stand outside the door, because they aren't on it. MCP tools stay registered, but `codemode` and `tool_search` aren't on it either, so nothing reaches them. Planning a read-only lookup? `readOnlyTools()` and `harnesses_info` give the list first.

Sessions are JSONL per project under `~/.pi/agent/sessions/`, with UUIDv7 ids, and the directory moves with `PI_CODING_AGENT_SESSION_DIR` or `--session-dir`. `.pi/SYSTEM.md` replaces the system prompt and `APPEND_SYSTEM.md` appends to it. `.pi/prompts/` holds reusable Markdown prompts invoked as slash commands, so those paths appear in both `promptTemplates` and `commands`. The Pi extension in this package registers the eleven tools in Pi itself.

MCP servers? Since 0.99 Pi has them built in, in `~/.pi/agent/mcp.json` and `.pi/mcp.json`. The project file counts only once you trust the project. `sse` is out, Pi wants stdio or streamable HTTP.
