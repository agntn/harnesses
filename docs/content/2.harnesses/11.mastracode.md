title: Mastra Code

::harness-facts{id="mastracode"}
::

Mastra Code stores everything it remembers in one LibSQL database under `~/.local/share/mastracode/` on Linux, threads and messages alongside its observational memory. Hooks are a JSON file rather than a directory, at project and user scope, and MCP servers sit in `.mastracode/mcp.json` and its global twin.

It reads Claude's files as its own: `CLAUDE.md`, `.claude/CLAUDE.md`, `~/.claude/CLAUDE.md` and both skills directories, beside `AGENTS.md` and `.mastracode/`. No non-interactive mode is recorded, so `invoke` rejects before spawning and the CLI's `run` refuses it with the same message. Both `mcp.json` files are the plain `{ command, args, env }` and `{ url, headers }` family, so `listMcpServers` reads them and `syncMcpServers` rewrites the user one. The `type` field means nothing to Mastra Code: an entry is stdio when it has `command`, HTTP when it has `url`, and SSE gets settled at connect time. That's why the registry gives it its own `mastracode` dialect. A stale `type` next to a `command` doesn't turn the listing into SSE, and the writer leaves `type` out. It also picks up `mcpServers` from the project's `.claude/settings.local.json`, below both of its own files. The registry leaves that one alone, it's Claude's file and Claude itself keeps MCP servers elsewhere.
