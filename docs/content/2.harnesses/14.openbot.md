---
title: OpenBot
description: A desktop app that hosts CLI agents. Its state lives in Electron userData and every run mode is refused.
---

::harness-facts{id="openbot"}
::

OpenBot is a desktop app by nightly-labs, not a CLI. It hosts Codex, Claude Code, Grok and other CLIs as persistent agents. There's no headless mode, so every run mode is refused. Ask for `--version`? You'd start the app instead. The registry reports `null` rather than probe.

Its state lives in Electron's userData directory. On Linux, that's `~/.config/OpenBot/`, unless `XDG_CONFIG_HOME` moves it. The `openbot.db` database holds agents, conversations, routines and MCP servers. I like having one source of truth here. MCP servers are edited in the app, so the registry can't sync them.

OpenBot reads your skills from `~/.agents/skills/`. That's the folder Codex's skills sync uses, so syncing Codex covers OpenBot. It leaves out skills the hosted CLI already loads. Skills made in the app live in `local-skills/` under userData, with an immutable directory for each revision.

Each agent has a workspace under `~/OpenBot/Agents/<agent-id>/`. Its rules live in `AGENTS.md` at the workspace root. Older workspaces keep `CLAUDE.md`. There's no single user file for `agents sync` to update. The hosted CLI still reads its own user instructions.

OpenBot sets `OPENBOT_AGENT_PROCESS=1` on every CLI it starts. A hosted CLI with its own marker takes precedence. Codex sets none, so a Codex agent detects as `openbot`. On Linux, an AppImage install can show a hollow dot in `harnesses detect`. The `openbot` command is on `PATH` only with the Nix package.
